# Omnichannel Marketing Attribution — Power BI

Multi-touch marketing attribution, funnel conversion and cost-efficiency analytics,
built as code end to end: SQL Server data platform → Power Query → semantic model
(TMDL) → report (PBIR).

> **Synthetic data.** Every table in this project is synthetic and portfolio-safe.
> It must never be presented as a real company's marketing or revenue data.

![Executive Summary](Validation/evidence/listing/executive.png)

## What it answers

- Which channels and campaigns earn credit for revenue — under **five attribution
  models** (First Touch, Last Touch, Linear, Position-Based, Time-Decay), switchable
  in the report — and **where the model choice actually changes the answer**.
- Where leads drop out of the **Lead → MQL → SQL → Opportunity → Customer** funnel.
- What each lead, acquisition and customer costs (**CPL, CPA, CAC, ROAS**) by
  channel, campaign and region — in one constant reporting currency.
- How far the source data can be trusted, and what was done about it.

## Built to survive an expert's cross-check

Every number on every page is reconciled to an independent SQL query at the grain the
visual shows it (2,552 live checks), and the report follows the rules an analyst would
check first:

- **One as-of date (31 Aug 2026) for every figure.** The source records outcomes seven
  weeks later; a customer counts only once revenue is booked by the as-of date, so
  customers, revenue and deal size reconcile with each other.
- **Attributed revenue is dated by booking date**, so under every model each month's
  attributed revenue equals the revenue finance booked that month.
- **Complete periods and mature cohorts only** in trends — no partial quarter or
  still-converting cohort drawn as a collapse; growth is like-for-like year to date.
- **Differences are coloured only when larger than chance** (binomial and fair-share
  z-tests), and media rates that are identical on every channel are not ranked.
- **The ad/CRM scale gap is disclosed, never rescaled**: absolute ROAS, CPL and CAC sit
  beside a data note and the scale-free Revenue-to-Spend Index leads.

## Architecture

```
Data/raw/*.csv ──BULK INSERT──▶ stg (text landing)
                                  │  typed, constrained, derived
                                  ▼
                                dbo (star schema, trusted FKs, FX, attribution credit)
                                  │  contract
                                  ▼
                                analytics.vw_*  ──Power Query──▶  semantic model (TMDL)  ──▶  report (PBIR)
```

| Layer | Holds |
|---|---|
| `stg` | One NVARCHAR landing table per CSV, so a bad value can never abort a load |
| `dbo` | Typed star schema; 25 engine-trusted foreign keys; FX planning rates; `FactAttributionCredit` (874,690 rows) |
| `analytics` | 17 views — the only objects Power BI reads |
| Semantic model | 13 tables, 12 relationships, 83 measures, dynamic regional RLS — generated by `Python/02_generate_semantic_model.py` |
| Report | 7 pages behind a navigation rail, 154 visuals of 23 types, in a dark neon "command centre" theme (registered custom theme) — generated by `Python/04_generate_report.py` |

## Build

Requires SQL Server 2022+ (Express is enough), `sqlcmd`, Power BI Desktop, and
Python 3 with pandas, pyodbc and jsonschema.

```powershell
python Python\01_data_audit.py                          # audit the raw files
powershell -ExecutionPolicy Bypass -File SQL\run_all.ps1   # build and validate the database
python Validation\validate_attribution.py               # SQL attribution vs independent Python
python Python\02_generate_semantic_model.py             # write the semantic model
python Validation\verify_semantic_model.py              # model vs live SQL views
python Python\04_generate_report.py                     # see the warning below
python Validation\validate_report_layout.py             # navigation, overlap, titles, ranking rules
powershell -ExecutionPolicy Bypass -File Validation\open_powerbi.ps1          # open + refresh via the engine
powershell -ExecutionPolicy Bypass -File Validation\reconcile_measures.ps1
python Validation\generate_visual_queries.py | Set-Content $env:TEMP\q.dax
powershell -ExecutionPolicy Bypass -File Validation\validate_visuals.ps1 -QueryFile $env:TEMP\q.dax
python Python\03_generate_measure_dictionary.py
```

No machine path is committed. The SQL source is named once, in the model parameters
`SqlServer` and `SqlDatabase`.

> **`04_generate_report.py` overwrites `PowerBI/…Report/`.** The report checked in here
> was finished by hand in Power BI Desktop after the generator last ran, so the
> generator no longer knows about it. Treat the committed PBIR as source and edit it in
> Desktop; run the generator only on a copy, or to rebuild the report from scratch on
> purpose. The other steps above are safe to re-run.
